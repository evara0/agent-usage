# 真实验证设计

## Context
所有运行资料保存在 Git 忽略的 .local/live-hook-validation。CODEX_HOME 仅对子进程生效。测试脚本只写固定测试名和执行时间到同目录标记，不复制认证、不修改个人全局 Hook 配置。

## Decisions
保持正常信任流程，用户在隔离 CLI 登录并审查具体 Hook。单独 thread/start 后未取得执行证据；将观察窗口扩展到 15 秒后仍为零，因此比较首次 turn/start。用户明确授权一次最小模型请求，输入仅要求回复 OK、不使用工具；收到 Hook 完成通知后立即中断 turn。

只保存实际收到的原生通知，不手写或补齐成功结果。依据同一 thread/run、实际标记和采集窗口核对开始/结束及 Unix 秒单位，再导出显式声明单位的离线文件。真实通知和认证不入库。

## 验证历史与结果
首次隔离 CLI 因执行策略和 PATH 问题未能打开，改由完整 exe 路径进入。用户完成登录后第一次复核仍为 untrusted，继续正常审查后变为 trusted。此前 thread/start 单独验证没有通知或标记，不能据此认定适配器错误。首次模型请求命令曾因授权范围不足被自动审批拒绝，没有执行；用户明确回复 ok 后才执行。

本机 codex-cli 0.163.0-alpha.10.2 的 thread/start 观察阶段 15 秒无信号；首次 turn 阶段获得真实开始和 completed 通知、执行标记。未修改的 CLI 返回调用 1、成功 1、失败 0、未知 0、耗时样本 1、总耗时 756 ms，质量错误为零。结果限于此版本和这次同步 command Hook，不证明所有版本触发规则、历史完整性或异步覆盖。详细证据与复查命令见 docs/live-hook-validation.md。
